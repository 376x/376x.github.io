FastAPI 依赖注入 Depends 的正确打开方式

2026-08-10 # FastAPI# Dependency Injection# Python

很多教程把 Depends 讲成"给路由函数传参的工具"，这只是它的表面。 依赖注入（DI）真正的价值在于：把横切逻辑从业务代码里抽离出去， 并让框架帮你管理它们的生命周期。这篇文章整理我在项目中反复使用的几种模式。

1. 从最普通的依赖开始

任何可调用对象都可以作为依赖：普通函数、async 函数、类实例化。

from typing import Annotated
from fastapi import Depends, FastAPI

app = FastAPI()

async def pagination(page: int = 1, page_size: int = 20) -> dict:
    """校验并规范分页参数"""
    if page > 100:
        raise ValueError("page too large")
    return {"page": page, "page_size": page_size}

@app.get("/items")
async def list_items(params: Annotated[dict, Depends(pagination)]):
    offset = (params["page"] - 1) * params["page_size"]
    return fetch_items(offset=offset, limit=params["page_size"])

注意：查询参数声明出现在了依赖 pagination 里。 FastAPI 会把依赖的签名递归地纳入 OpenAPI 文档， 所以 Swagger UI 上会自动出现 page 和 page_size 参数 —— 校验和文档都免费获得。

2. Annotated 别名：一次声明，处处复用

每次都写 Annotated[dict, Depends(pagination)] 太啰嗦。 用类型别名把它固化下来，这是 FastAPI 官方目前推荐的风格： 

from typing import Annotated
from fastapi import Depends

PageParams = Annotated[dict, Depends(pagination)]

@app.get("/items")
async def list_items(params: PageParams): ...

@app.get("/orders")
async def list_orders(params: PageParams): ...

业务代码只剩一个干净的 params: PageParams， 校验逻辑的修改集中在 pagination 一处 —— 这就是 DI 带来的解耦。

3. yield 依赖：不只是注入，还有"善后"

生成器函数可以作为依赖：yield 之前的代码在请求进入时执行， 之后的代码在响应返回后执行 —— 天然的资源管理钩子，类似 contextmanager： 

from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker

SessionDep = Annotated[AsyncSession, Depends(get_db)]

async def get_db() -> AsyncIterator[AsyncSession]:
    async with session_factory() as session:
        try:
            yield session              # ---- 请求处理阶段 ----
            await session.commit()     # 业务没有抛异常才提交
        except Exception:
            await session.rollback()
            raise

@app.post("/orders")
async def create_order(payload: OrderIn, db: SessionDep):
    order = Order(**payload.model_dump())
    db.add(order)
    await db.flush()
    return {"id": order.id}
  • commit/rollback 收口在依赖里，路由函数再也不用关心事务边界；
  • 即使业务抛出异常，yield 之后的清理代码依然会执行；
  • 同一请求内多个地方依赖 get_db 时，默认 use_cache=True 会复用同一个 session，不会重复建连。

4. 依赖嵌套：组合出复杂逻辑

依赖本身也可以有自己的依赖，FastAPI 会构建一棵依赖树并逐层解析：

from fastapi import Header, HTTPException, status

async def verify_token(
    x_token: Annotated[str, Header(alias="X-Token")]
) -> str:
    if not await redis.sismember("valid_tokens", x_token):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid token",
        )
    return x_token

TokenDep = Annotated[str, Depends(verify_token)]

async def current_user(token: TokenDep, db: SessionDep) -> User:
    user = await db.get(User, decode_token_to_id(token))
    if user is None:
        raise HTTPException(status_code=404, detail="User not found")
    return user

CurrentUser = Annotated[User, Depends(current_user)]

@app.get("/me")
async def me(user: CurrentUser):
    return user

注意 current_user 同时消费了 TokenDep 和 SessionDep， 而这两者各自可能又有更深层的依赖。你只需要声明"我需要什么"，解析顺序、缓存、生命周期都交给框架。

5. 路由组级依赖：批量挂鉴权

如果一个 APIRouter 下所有接口都需要登录，不必逐个添加参数：

from fastapi import APIRouter, Depends

admin_router = APIRouter(
    prefix="/admin",
    dependencies=[Depends(require_admin)],   # 只做门禁，不注入值
)

@admin_router.delete("/users/{uid}")
async def delete_user(uid: int):
    # 能走到这里说明 require_admin 已通过
    ...

dependencies=[...] 里的依赖会被正常执行和校验，只是返回值不会注入到路由函数 —— 特别适合鉴权、限流、审计日志这类"只检查、不使用结果"的场景。

小结

  • 可调用对象皆依赖：函数、async 函数、类都行；
  • Annotated 别名是现代 FastAPI 项目里依赖复用的标准姿势；
  • yield 依赖 = setup + teardown，把事务、连接的收口代码移出业务层；
  • 依赖树自动解析与缓存，复杂的组合逻辑拆成小依赖即可；
  • 路由组级 dependencies 用于不注入值的横切检查。

把这些模式用熟之后，你会发现 FastAPI 项目的分层可以非常干净： 路由薄薄一层做协议转换，业务收敛在 service，资源与横切逻辑全部由依赖树托底。
