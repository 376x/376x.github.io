Pydantic v2 实战：更快、更严格的输入校验

2026-08-26 # FastAPI# Pydantic# 迁移实践

Pydantic v2 把校验核心用 Rust 重写（pydantic-core），基准测试的序列化/反序列化速度普遍有数倍提升。 对以 I/O 校验为日常的 FastAPI 项目来说，这是最值得升级的一次大版本。 不过 v2 的 API 变化不小，这篇文章整理迁移中最常踩的点和新写法。

1. 高频破坏性变更速查表

v1 写法v2 写法
class Config:model_config = ConfigDict(...)
.dict() / .json().model_dump() / .model_dump_json()
.parse_obj() / .parse_raw().model_validate() / .model_validate_json()
@validator@field_validator
@root_validator@model_validator
orm_mode = Truefrom_attributes = True
.schema().model_json_schema()

好消息是官方提供了 bump-pydantic 自动迁移工具，能机械替换大部分； 真正需要人工处理的，是下文这些"语义有变化"的地方。

2. 配置：ConfigDict 取代内嵌 Config 类

from pydantic import BaseModel, ConfigDict

class UserOut(BaseModel):
    model_config = ConfigDict(
        from_attributes=True,   # 原 orm_mode，支持 ORM 对象直接转换
        str_strip_whitespace=True,
        extra="forbid",          # 多余字段直接报错（默认 ignore）
    )

    id: int
    name: str
    email: str

在 FastAPI 中，返回 ORM 对象的响应模型现在只需要： model_config = ConfigDict(from_attributes=True)， 然后 @router.get(..., response_model=UserOut) 即可。

3. field_validator：字段级校验的新姿势

v1 的 @validator("field") 变成 @field_validator("field")， 且必须用 classmethod 风格书写。最大的变化是 mode 参数：

from pydantic import BaseModel, field_validator

class OrderIn(BaseModel):
    phone: str
    coupon: str | None = None

    @field_validator("phone")
    @classmethod
    def validate_phone(cls, v: str) -> str:
        """默认 mode="after"：拿到的是类型转换后的值"""
        cleaned = v.replace("-", "").replace(" ", "")
        if not (cleaned.isdigit() and len(cleaned) == 11):
            raise ValueError("手机号格式不正确")
        return cleaned

    @field_validator("coupon", mode="before")
    @classmethod
    def empty_to_none(cls, v: object) -> object:
        """mode="before"：拿到原始输入，适合清洗脏数据"""
        if isinstance(v, str) and not v.strip():
            return None
        return v

经验法则：清洗数据用 before，校验业务规则用 after。 before 拿到的是未转换的原始输入，after 拿到的已经是目标类型的实例。

4. model_validator：跨字段校验

from typing import Self
from pydantic import BaseModel, model_validator

class DateRange(BaseModel):
    start: datetime
    end: datetime
    min_days: int = 0

    @model_validator(mode="after")
    def check_range(self) -> Self:
        if self.end < self.start:
            raise ValueError("end 不能早于 start")
        if (self.end - self.start).days < self.min_days:
            raise ValueError(f"间隔至少 {self.min_days} 天")
        return self

mode="after" 的 model_validator 拿到的是已构造完成的模型实例（所以是 Self），做跨字段一致性检查非常顺手。

5. Annotated + Field：约束复用

把常用的约束条件抽成类型别名，整个项目的入口校验风格就统一了：

from decimal import Decimal
from typing import Annotated
from pydantic import Field

Amount = Annotated[Decimal, Field(ge=0, decimal_places=2)]
PageNum = Annotated[int, Field(ge=1, le=10000)]

class RefundIn(BaseModel):
    order_id: int
    amount: Amount
    reason: str = Field(min_length=5, max_length=200)

6. computed_field：模型派生字段进序列化

from pydantic import BaseModel, computed_field

class Product(BaseModel):
    price: Decimal
    tax_rate: float

    @computed_field  # type: ignore[prop-decorator]
    @property
    def price_with_tax(self) -> Decimal:
        return (self.price * Decimal(str(1 + self.tax_rate))).quantize(Decimal("0.01"))

导出到 JSON 时 price_with_tax 会自动出现在结果里，并且进入 OpenAPI schema。

7. 序列化控制的常用开关

order = Order.model_validate(raw)

order.model_dump()                        # dict，默认包含全部字段
order.model_dump(exclude_unset=True)      # 只含用户显式传入的字段（PATCH 局部更新神器）
order.model_dump(exclude={"internal_id"})
order.model_dump(by_alias=True)           # 输出别名（如 camelCase API 字段）
Order.model_validate_json(json_bytes)     # 直接从 bytes 解析，走 Rust 快速通道

重点推荐 PATCH 场景用 exclude_unset=True： 只有调用方显式传了的字段才会进入更新字典，再也不用手写一堆 if "field" in body。

小结

  • 先跑 bump-pydantic，再手动处理校验器和配置的语义差异；
  • mode="before" 清洗脏数据、mode="after" 做业务校验；
  • 约束收敛到 Annotated 别名，全项目校验口径一致；
  • PATCH 更新配 exclude_unset=True，省掉大量样板代码。
